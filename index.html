Why Keysi exists
“This app used to exist.”

CheatSheet, by Media Atelier, did exactly this for years — hold a key, see the frontmost app's shortcuts. It stopped working on macOS Sonoma and was discontinued.

Most people assumed Apple had removed the API it needed. Apple didn't. The accessibility API Keysi depends on (AXUIElementCreateApplication and the menu-bar attributes) is still public and still works — verified directly against TextEdit, Safari, Finder, Xcode, VS Code, Slack, and Figma.

Keysi is a new implementation of a technique that was never actually deprecated. This project exists because a good tool disappeared, not because the technique stopped working.

Not affiliated with Media Atelier. Keysi shares no code with CheatSheet — it's a new app built on the same public API.

Real keycaps, real groupingFree

Shortcuts, organized the way the app already is.

Every shortcut renders as a real macOS-style keycap — ⌘⇧S — not the string "Cmd+Shift+S". Grouped by menu, with a breadcrumb for anything nested in a submenu, so you can also find it by hand next time. Items the app has currently disabled show up dimmed, because a shortcut you can't use right now isn't a shortcut.

Being upfront

Two modes, one honest difference.

Hold-⌘ is a glance. You can't type to search while holding it down — and that's deliberate, not an oversight.

⌘ Hold

A global event monitor can observe keystrokes, but it can't consume them — so anything you typed while holding ⌘ would still reach the app underneath. Keysi won't install the kind of input tap that could change that. Hold-⌘ shows you everything; it just can't filter it.

⇧⌘K Panel

Press the hotkey instead and the same content opens as a real interactive panel: type to filter, use arrow keys to move, press Escape to dismiss. Fully searchable, on purpose.

Keysi reads other applications' menu structure through the Accessibility API. Apple has confirmed directly that this does not work inside the App Sandbox, which the Mac App Store requires for every app. Every comparable tool — KeyCue, KeyClu, the original CheatSheet — ships the same way: signed with a Developer ID certificate and notarized, distributed directly.

FAQ

Questions worth answering upfront.

Why does Keysi need Accessibility access?

To read the menu bar of the app you're currently using, so it can show its keyboard shortcuts. Verbatim, from the permission prompt: "Keysi needs Accessibility access to read the keyboard shortcuts of the app you're using. It never controls your keyboard or mouse without an explicit click on a shortcut row."

Does Keysi send anything anywhere?

Two network calls happen on their own: a license check to Gumroad, and an update check against Keysi's Sparkle appcast. Nothing about your menus, the apps you use, or the shortcuts you press ever leaves your Mac.

Usage analytics are off by default. If you switch them on in Settings, Keysi sends a short list of product events — app launches, which Settings tab you open, the overlay appearing, which shortcut you triggered, and licensing events like a trial starting or an upgrade prompt being shown — to a EU-hosted PostHog instance. Your license key, the amount you paid, and the contents of any menu are never sent. Crash diagnostics are off by default and, when enabled, are generated on-device by Apple's MetricKit and never leave your Mac unless you copy and share them yourself. See the privacy page for the full list.

Why isn't Keysi on the Mac App Store?

The Accessibility API Keysi depends on to read another app's menu structure doesn't work inside the App Sandbox, which every Mac App Store app is required to use. This is a permanent constraint, not a launch-day limitation — every comparable tool (KeyCue, KeyClu, the original CheatSheet) ships the same way, direct and notarized.

Can I search while holding ⌘?

No. A global event monitor can observe your keystrokes but can't consume them, so anything typed while holding ⌘ would still reach the app underneath — Keysi won't install the kind of input tap that could change that. Press the global hotkey (⇧⌘K by default) instead: the same content opens as a real panel where search, arrow keys, and Escape all work.

Which macOS versions and Macs does Keysi support?

macOS 26 or later, on Apple silicon and Intel Macs.

How many Macs can I use my license on?

Up to 3 Macs at once. To move a license to a new Mac, open Settings → Keysi Pro → Deactivate This Mac on the old one, then activate on the new one with the same key.

What's your refund policy?

30 days, no questions asked. See Terms & refunds.

How do updates work?

Keysi checks for updates automatically via Sparkle. Every update is cryptographically signed and verified against a key built into the app before it installs. You can also check manually from the menu bar item: "Check for Updates…"

An app I opened shows no shortcuts — what's wrong?

This usually happens right after an app launches, or on its Welcome screen, before it has a real menu bar to read yet. Open a real document or project in the app and try again.

Does Keysi work with Electron apps like Slack or VS Code?

Yes — Slack, VS Code, and Figma all return correct menu trees. For the bindings that only exist in an app's renderer and never reach its native menu bar, built-in custom sheets fill the gap.

Is this the original CheatSheet?

No. Keysi is not affiliated with Media Atelier and shares no code with CheatSheet — it's a new, independent app built on the same public accessibility API.

What happens when the Keysi Pro trial ends?

Keysi keeps working. Every install starts with 14 days of Keysi Pro; when that runs out (after a short grace period) the app drops back to the free tier rather than stopping. Holding your modifier still shows every shortcut, clicking a row still runs it, your custom sheets still load. What stops is the coaching: the reminders, Practice Mode, the progress figures and the weekly summary. Nothing you wrote or configured is deleted, and upgrading later picks up where you left off — Keysi keeps counting locally the whole time, which is how it can show you what you missed.

Can I use a modifier other than ⌘ to trigger the overlay?

Yes. Settings ▸ Triggers lets you pick ⌘, ⌥, ⌃ or ⇧ as the hold modifier, and the hold delay is adjustable. Keysi will warn you about the trade-offs of the non-⌘ options — ⌥ also reveals alternate menu items, ⌃ overlaps with secondary click and Full Keyboard Access, and ⇧ can trip Slow Keys or Sticky Keys if you have them on — but it won't stop you choosing one. The global hotkey (default ⇧⌘K) is separately rebindable to any combination you like.
