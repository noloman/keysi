Troubleshooting

Why doesn't my Mac keyboard shortcut work?

You press the keys and nothing happens, or something else happens. Most of the time another app or macOS itself took the key first. Here are the usual causes, in the order worth checking, and how to find which app took it.

1. macOS takes it first

macOS's own shortcuts win over the app in front. ⌘Space opens Spotlight, ⌃Space switches input source, ⌃← and ⌃→ move between Spaces, and ⌘⇧3, ⌘⇧4 and ⌘⇧5 take screenshots. If an app gives one of these to a menu command, the command never fires.

Fix: open System Settings ▸ Keyboard, click Keyboard Shortcuts…, find the shortcut and turn it off or change it. Or give the app's command a different key: in the same window, open App Shortcuts, click +, pick the app, type the menu title exactly as it appears, and press the new keys. Type "…" with ⌥; (Option-semicolon).

2. Another app's global hotkey takes it

Launchers, window managers and remappers such as Raycast, Alfred, Rectangle, Karabiner-Elements, skhd and Hammerspoon listen for keys in every app. If one of them uses the key, the app in front never hears it. This is the most common cause after installing something new.

Fix: change the hotkey in that app's settings, or quit it for a moment and press the shortcut again to confirm it's the culprit.

3. Two commands in the same app share a key

It happens, especially after you add your own shortcuts. The app runs whichever command it finds first, which may not be the one you wanted.

Fix: give one of the two commands a different key, in the app's own settings or as an App Shortcut (see step 1).

4. The command isn't available right now

A greyed-out menu item does nothing when you press its shortcut. Check the menu: many commands need a selection, an open document or a particular mode. Also check that the right app is in front, and that focus isn't in a text field that uses the key itself.

Fix: click into the document or window the command acts on, select something if it needs a selection, and try again.

5. A custom App Shortcut doesn't match the menu

In System Settings ▸ Keyboard ▸ Keyboard Shortcuts… ▸ App Shortcuts, the menu title must match exactly, including capitals and the "…" character (three dots typed as periods don't count). Some apps also need to be quit and reopened before a new App Shortcut works.

6. Function keys, modifier keys and keyboard layout

  • F1, F2 and the rest: on most Mac keyboards they control brightness and volume unless you hold fn. Turn on "Use F1, F2, etc. keys as standard function keys" under Keyboard Shortcuts… ▸ Function Keys if you use them a lot.
  • Remapped modifiers: if Caps Lock, ⌃, ⌥ or ⌘ was swapped under Keyboard Shortcuts… ▸ Modifier Keys, or by a tool like Karabiner-Elements, the key you press isn't the one the shortcut wants.
  • Keyboard layout: on non-US layouts, keys like ` [ ] and \ are elsewhere or need ⌥, so a shortcut written for a US keyboard can need different keys.

7. A password field is active

While a password field has focus, macOS turns on secure input, and some hotkey apps stop hearing keys until you leave the field. Some apps can also leave it on: Terminal's Secure Keyboard Entry, or a password manager that didn't turn it off again. If a launcher or window manager hotkey only fails sometimes, this is a likely reason. Keysi's overlay shows a lock while secure input is on.

Find which app takes a shortcut

Checking every app by hand is slow. Keysi's Shortcut Health (free, no trial) scans the menus of every running app, macOS's own shortcuts, your App Shortcuts, and global hotkeys from Raycast, Rectangle, Karabiner-Elements, skhd and Hammerspoon. It lists each collision it finds with one line saying who wins. You can also press any key combination to see everything Keysi can see that claims it. Hotkeys from apps it doesn't read yet, such as Alfred, Keyboard Maestro or BetterTouchTool, won't show up, so for those use the quit-and-retry check in step 2.

With Keysi Pro ($14.99 once), it puts the shortcuts Coach has seen you use first. It can fix a menu-shortcut collision by giving the losing command a free key, as a macOS App Shortcut: it asks first, and you can remove it in one click. Sandboxed apps, including most App Store apps, get step-by-step instructions instead. It also tells you when an app you open starts taking a key you use.
