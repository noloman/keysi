Mac keyboard shortcuts

How to see the keyboard shortcuts of the app you're using

macOS already gives you three ways to do this, and it's worth knowing them before installing anything. Two of them are a click away in the app you're already in. Each one stops somewhere specific, though, and this page is about where. Then it's about Keysi, which is the tool this site sells: it shows the frontmost app's whole shortcut list at once, and that part is free, with no time limit.

What macOS gives you, and where each one stops

  • The app's own menu bar. Every shortcut an app exposes as a menu command is printed right next to it. This is the real, authoritative list, but it's one menu at a time, and anything nested in a submenu stays invisible until you open that submenu. If you don't already know roughly where a command lives, you're hunting.
  • Search the menus from the Help menu. In most Mac apps, the Help menu's search field finds menu commands by name and shows you where they are. Genuinely useful, and underused, but it answers "where is the command I already have a name for", not "what can I do here". You can't browse what you didn't know existed.
  • System Settings ▸ Keyboard ▸ Keyboard Shortcuts. A complete, editable list of macOS's shortcuts. Mission Control, Spotlight, screenshots, input sources. It says nothing about the app you're in, which is usually the thing you were asking about.

Between them, the gap is the same shape every time: there's no way to see the whole of one app's shortcuts at once, at the moment you're using it, without leaving it.

What Keysi does instead: hold ⌘

Hold ⌘ for a moment and Keysi shows every shortcut of whatever app is frontmost, grouped by the menu it came from, with a breadcrumb for anything nested in a submenu, and each combination rendered as a real keycap (⌘⇧S) rather than the string "Cmd+Shift+S". Let go and it's gone. If you'd rather use a different key, the hold modifier is configurable: ⌘, ⌥, ⌃ or ⇧.

It isn't a stored list of shortcuts per app. Keysi reads the app's live menu structure through the macOS Accessibility API at the moment you ask, which is why it works in apps nobody wrote a cheat sheet for, and why a command the app has currently disabled shows up dimmed instead of misleading you.

The same reading produced the shortcut lists for Xcode, Keynote, Finder, Mail and other Mac apps on this site, if you'd like to read one before installing anything.

And because it's the live menu rather than a picture of one, clicking a row runs that command. Which matters more than it sounds for the case you're probably in: you looked the shortcut up because you wanted the thing done. Click it now, read the keycaps on the way past, and learn it on the third or fourth time instead of the first.

The list itself is free, with no time limit. Hold your modifier, see every shortcut, click one to run it.

When the shortcut is printed but nothing happens

This is the failure the menu bar can't warn you about. macOS claims some key combinations for itself, and a system shortcut wins before the keystroke ever reaches the app, but the app's menu prints its shortcut either way, so the only feedback you get is that nothing happened. Keysi reads macOS's own shortcut assignments and marks the rows the system will intercept, so you find out while you're looking at the list rather than by pressing keys at an app that can't hear them.

Apps whose real shortcuts aren't in a menu at all

Reading the menu bar only works when the shortcuts are in the menu bar. Plenty aren't. Figma and Slack keep most of theirs elsewhere, and a terminal program like Vim or tmux has no Mac menu bar to put them in. For those, Keysi uses custom cheat sheets: hand-written lists that attach to an app by identity. Figma, Slack, Vim and tmux ship built in, and there's an editor for writing your own for any app, with no JSON by hand unless you want to.

The Vim and tmux sheets work because Keysi looks inside your terminal rather than just at it: for a known terminal emulator (Terminal, iTerm2, Ghostty, Warp, Alacritty, WezTerm, kitty, Hyper, Tabby) it detects which program is actually running in the foreground, and matches sheets against that. With several tabs or splits open it works out which one you're looking at from the terminal's own window title, and falls back to showing sheets for everything running across them when that's inconclusive, right most of the time, not guaranteed.

Seeing the list is not the same as using it

Worth saying plainly, because it's the part a cheat sheet doesn't fix: looking a shortcut up is a thing you can do a hundred times and still reach for the menu on the hundred-and-first. A reference waits to be asked.

That's what Keysi Pro ($19.99, one payment, three Macs) adds. Shortcut Coach notices when you pick a menu command with the mouse that already has a keyboard shortcut, and offers one quiet, dismissible reminder; Practice Mode drills the ones you keep missing; and Keysi times how long your own menu trips actually take, so the figures it shows you are arithmetic on two things it counted rather than an industry average. Pro also makes Keysi reachable from outside itself: Raycast, Shortcuts, Spotlight, Siri, and the Services menu.

Everything on this page above that section is free, with no time limit, no account and no card: the overlay, the searchable panel, click-to-run, custom sheets and their editor, and the interception warnings. Every install starts with 14 days of Pro on top, and when that runs out Keysi drops back to the free tier rather than stopping.

One honest limitation

You can't type to search while you're holding the modifier. A global event monitor can observe keystrokes but not consume them, so anything you typed would still land in the app underneath, and Keysi won't install the kind of input tap that could change that. Press the global hotkey instead (⇧⌘K by default) and the same content opens as a real panel, where search, arrow keys and Escape all work. It's a deliberate trade rather than an oversight.

What it needs

macOS 14 or later, and Accessibility permission. That's the API that reads another app's menu structure, and there's no way to do this without it. Keysi is distributed directly rather than through the Mac App Store, because the sandbox the App Store requires blocks that API outright; it's signed with a Developer ID certificate and notarized by Apple. The FAQ covers exactly what the permission does and doesn't allow, and the privacy page lists every network call the app makes.
